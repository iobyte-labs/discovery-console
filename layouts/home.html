How it runs

Four steps, twice a week

Each step picks its own work out of the dataset, so a step with nothing to do costs seconds rather than breaking a chain.

  1. You add an association Paste the page that lists its members. No selectors, no code.
  2. It reads the members The companies a directory links to are very largely its members. Each record says how it was found, because a sponsor looks the same as a member.
  3. It visits each company's own site Careers page, contact page, imprint, homepage last — stopping at the first address that is meant for applications.
  4. You read the result Filter by country, sector, status or evidence, and see where every address came from.

What it will not do

The lines it does not cross

Guess an address

No first.last@company construction, no probing to see what bounces. An address is recorded because a page published it, with that page named, or not at all.

Keep a person's address

An address naming an individual is dropped where it is found and refused again on the way into the database. A functional mailbox is business contact information; a named person's is not.

Work around a refusal

A robots rule, a login wall or a hard refusal is recorded as a result and left alone. No retries dressed up as someone else.

Hammer a small server

Ten requests a minute per domain, one page at a time per site, with every crawl bounded by a deadline it stops cleanly at.

Publish your data

This site is a static shell with nothing in it. The dataset lives in a private repository and reaches your browser only after you sign in.

Send anything

No mail leaves here, and no application is written here. That belongs to a separate private tool that never runs in CI.
